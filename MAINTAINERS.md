# Maintainers — FED-Radio

Who runs the project and how to reach them.

| Name | Role | Reach |
|---|---|---|
| FedPromptly | Founder & Lead maintainer — final say, releases, keys | Open a [Discussion](../../discussions) or a private security report (see [SECURITY.md](SECURITY.md)) |

## Responsibilities

- Reviewing and merging PRs (with the [ground rules](GOVERNANCE.md) enforced)
- Cutting releases and maintaining the changelog
- Holding the release keystore **if/when one is created** (until then, debug
  builds are the distribution format — see [DEPLOYMENT.md](DEPLOYMENT.md))
- Responding to security reports per [SECURITY.md](SECURITY.md)

## Response targets (not guarantees)

| Channel | Target |
|---|---|
| Security reports | 72 hours to acknowledgment |
| Bug issues | a few days |
| PR reviews | within a week |

## Becoming a maintainer

There's no formal process — it's a do-ocracy. Consistent, high-quality
contributions over time get you commit access when the lead says so, and a
row in this table. Everything else is in [GOVERNANCE.md](GOVERNANCE.md).
